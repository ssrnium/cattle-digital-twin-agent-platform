# 离线缓存 72 小时：容量口径与策略（2026-09-20）

> 验收标准要求"结构化事件离线缓存 ≥72h"。本文先定义容量口径，再说明调度与确认策略；实测证据见 `acceptance/cow_72h_capacity.py`（51,840 条等量灌库 + 断点续传 + 幂等抽样，结果记入 PROJECT_STATUS）。

## 一、容量口径

```text
设备数量        1 台边缘节点（edge-node-01，20号牛棚）
事件频率        1 条 / 5 秒（模拟器默认 interval=5）
缓存时长        72 小时
事件条数        1 × (72×3600/5) = 51,840 条
单条大小        ≈ 600-800 B（完整事件契约 JSON）
SQLite 体积     约 30-40 MB（实测见验收输出）
```

结论：演示规模下 SQLite 本地缓存 72h 数据量**无容量压力**（MB 级），因此 `wal_buffer` 不设条数上限；生产多设备场景按同一公式线性放大（10 台 ≈ 52 万条 / 300-400MB，仍可在边缘节点本地承载）。

## 二、调度与确认策略

| 策略 | 实现（`cow-edge/simulator.py`） |
| --- | --- |
| 优先级 | `LAMENESS` / `DEVICE_OFFLINE` 记 `HIGH`，其余 `LOW`；断网期间每 5 条周期性缓存一条 `DEVICE_OFFLINE(HIGH)` 作为设备侧自证 |
| 心跳降级 | 心跳连续失败 3 次后停用，仅写本地；`SYNC_STATE`（含 pending_count/last_sync_at）转 `LOW` 缓存待补传 |
| 补传顺序 | 恢复后先 `HIGH` 后 `LOW`，**服务端确认成功才删除本地记录**（成功才删 → 天然断点续传） |
| 中断恢复 | 补传进程被中断后重跑，剩余 pending 继续；服务端按 `event_id` 幂等去重，边界重发不产生重复 |
| 上限行为 | 当前不设上限（MB 级）；如需上限，建议超上限时丢弃最旧 `LOW` 并告警（未实现，属后续项） |

## 三、测试设计（三组）

1. **等量容量**：一次写入 72h 等量 51,840 条（主体 `SYNC_STATE(LOW)`，每 5 条 1 条 `DEVICE_OFFLINE(HIGH)`），断言吞吐、体积、分布；
2. **断点续传**：补传进程 kill 后重跑，验证"成功才删"语义下无丢失、最终 pending=0、服务端条数精确相等；
3. **幂等**：服务端 `count(DISTINCT event_id)` 等于总量；抽样重发全部返回 `duplicated=true`。

> "压缩时间窗"（如 offline --duration 600）只验证时间逻辑，不能代替本容量测试——本条即按此原则执行。
